# 教程发布前时间不够：先查哪条事实，卡住后怎么办？

> 本地 CLI 实跑改稿样本。依据为作者编写的测试资料，未验证方法效果。

发布前只剩一段固定的核查时间，可以先试行一个顺序：按事实出错后的操作后果安排核查，遇到证据阻塞就留下回查规则，再处理下一条。下面的排序、任务计数、切换和发布规则是独立建议，尚未经过真实教程案例验证。

1. 把教程拆成可核对的主张

先区分可核实事实与个人判断，对影响读者操作结果的主张保留原句、出处和核对日期。

逐段检查教程，把版本要求、操作条件、命令效果等事实单独列出。一句话包含多个可独立判断的事实时，拆开登记，同时保留原句。个人偏好另列；“我觉得好用”不能替代对功能是否存在的核对。

台账可直接采用这些字段：原句｜影响的步骤｜出错后果｜依赖它的其他步骤｜出处与支持段落｜核对日期｜状态｜等待原因与回查条件。

2. 先排操作后果，再考虑步骤依赖

建议先查出错后会使关键步骤失败的主张；后果相近时，尝试优先核查会影响其他步骤判断的主张。这个细分顺序是本文提出的假设，材料没有证明它最有效。

例如，在一个假设的文件导出教程中，“导出是否覆盖原文件”可排在“按钮位于哪个菜单”之前，因为前者关系到原文件能否保留。如果后续步骤都依赖某个版本才有的功能，也可先确认版本条件。例子只演示排序，不代表任何具体软件的行为。

3. 用证据决定是否完成

保存链接不等于核查完成，还需要阅读来源上下文，确认它是否支持具体主张。

建议将“完成”限定为：已经检查来源的适用条件，并确认它支持稿件中的具体表述。只支持部分条件，就修改表述后重新核对；来源含糊或相互冲突，就继续标为未核实。记录支持段落和核对日期，方便回看判断依据。

来源变化后，需要重新检查依赖该来源的结论。

4. 卡住时留下回查位置

材料介绍的团队看板通过限制正在处理的任务数量，尝试减少切换并识别瓶颈；这是方法的目的，不能直接当作个人作者已获得的收益。

个人试行时，可把状态分成“未开始、正在核查、等待证据、已核实”，并先固定计数规则：

- 未开始：尚未着手核查，不占正在核查的名额。
- 正在核查：已经开始、尚未完成，且未进入等待外部证据状态。包括已开始但暂时切出的任务；即使眼下没有处理它，它也仍占一个名额。
- 等待证据：只有下一步必须等待外部证据时才进入，例如已向维护者询问适用条件，正在等回复。仅仅查得慢、还没读完资料或想换一条处理，都不算等待外部证据。
- 已核实：达到前述完成标准，释放名额。

遇到外部证据阻塞，写清缺少什么证据、等待谁或哪个渠道提供，以及回查时点或触发条件，再转向下一条优先主张。本轮可约定等待项不计入正在核查的上限，但必须保留在总台账中，保留原有优先级，并单独统计数量和等待时长。证据到位不等于核查完成；恢复处理时，应将该项转回“正在核查”，重新计入名额，再检查证据是否支持原主张。发布前还要检查所有高优先级等待项。

正在处理的任务数量上限取决于任务复杂度和人员能力，并非越低越好。

可以先试上限为1，再在后续教程中试2；这两个数只是试验设置。上限为2表示最多保留两条正在核查的任务，不要求一定开启第二条。开启第二条前，应确认尚有名额，并为暂时切出的第一条写下返回条件；两条都未完成、也都没有等待外部证据时，不能再开第三条。

例如，在假设的文件导出教程中，作者先核查A“导出是否覆盖原文件”。读到相关说明后，发现需要先确认版本适用范围，于是记下A的阅读位置，开启B“该说明适用于哪些版本”。此时A虽被暂时切出，仍占一个名额；加上B，正在核查数为2。作者约定：核实B后立即回到A；如果B也卡在仍可自行查阅的资料上，则在预先设定的回查时点返回A，B仍占名额。如果B必须等待维护者回复，才将B转入“等待证据”，记录回查条件，并返回A检查现有资料中可继续核对的部分。若A也必须依赖这份外部回复才能继续，应如实记录同一阻塞，再将A转入等待状态。这个例子只说明计数与切换，不代表任何具体软件的行为。

等待项的证据到位后，按原有优先级安排恢复。如果正在核查的名额已满，先处理现有任务以释放名额，再恢复等待项；不能把另一条任务仅因暂时切出就改成等待状态来腾位置。比较不同设置时，应保持这些计数规则一致。使用这套方案的前提，是主张能拆成可独立核对的任务，且能区分主动核查与等待外部证据；任务上限本身不负责判断事实的重要性。

5. 时间用完，处理未核实内容

逐条列出未核实主张及其影响，再按以下拟议规则处理：不影响教程成立的内容可以删去；已有证据支持较窄结论时，可以缩小表述；关键操作仍依赖未核实事实时，延后发布。保留的不确定信息应明确标注，不能只加一句“尚未核实”就把它作为读者执行关键步骤的依据。删改后，重新检查相关步骤是否仍然成立。

将任务数量限制用于个人编辑，需要小规模试验并记录核查等待时间及漏查情况，现有材料尚不能证明它提高了个人核查效率或降低了错误率。

连续几期使用相近的核查时间预算，记录关键主张已核实数与总数、等待时长，以及时间耗尽时的处理决定。复盘时重新逐条检查正文中的操作事实，与台账及证据对照，分别记录遗漏登记、已登记但未核实，以及原先核实有误的情况。尽量记录任务复杂度，避免把教程难度不同造成的差异归因于任务上限。这种复查仍可能漏掉问题，结果只能帮助调整下一轮试行，不能直接证明错误率下降。
