## 二、首次打开与界面总览

### 1. 唤起工作台
- 打开桌面端 Obsidian（版本 1.8+）；
- 进入 **设置 → 社区插件**，确认 **OpenContent** 处于启用状态；
- 点击右侧功能区图标（或按 `Ctrl+P` 输入 `OpenContent: 打开工作板`）；
- 插件默认在 **右侧栏** 打开，不抢占中央笔记编辑区。

### 2. 三大核心导航区
顶部导航栏分为三个主入口：
- **首页**：灵感起点。支持“说一句想写什么”，快速基于当前打开的笔记创建项目，或查看最近进行中的文章。
- **写作**：日常工作台。左侧/上方为文章正文与多章节切换，下方为指令交互区与改稿提案，展开可查看依据证据链与五轴雷达。
- **发布**：交付中心。提供三套高颜值排版主题预览、一键复制富文本至公众号/知乎、Markdown 读者稿导出、以及微信公众号草稿箱回读。

### 3. 双模切换（极简 vs 专家）
- 界面顶部设有模式胶囊按钮：
  - **⚡ 极简创作模式**（默认）：只展示核心正文、快捷指令与清晰的定稿状态，适合专注行文；
  - **🛡️ 专家门禁模式**：展开五轴雷达分数（Evidence, Logic, Originality, Voice, Utility）、Claim 详细卡片、材料引用对照与历史 Diff。

## 三、核心场景操作指南

### 场景 1：基于当前笔记极速成文

适合场景：在日常阅读中记录了一篇读书笔记或零散想法，想快速扩写成一篇有理有据的完整文章。

1. **选择起点笔记**：
   - 在 Obsidian 编辑区打开你想作为底稿的笔记（如 `读书笔记.md`）；
2. **首页输入意图**：
   - 切换到 OpenContent 首页，输入框填写目标（例如：`给产品新手写一篇如何把碎片笔记变成文章的指南`）；
   - 确认勾选 **“使用当前笔记：读书笔记”**；
3. **点击「开始写作」**：
   - 系统自动创建 Content Project，并将当前笔记作为第一份 `Material` 存入项目中；
   - 自动调用本地 Agent CLI 执行 `distill`（提炼知识）→ `research`（提取主张与引文）→ `draft`（起草正文）；
4. **核对草稿与审查结果**：
   - 阶段自动推进至 `REVIEWING`（待审查），显示生成的草稿；
   - 查看五轴雷达：若全部显示 `PASS`，下方 **「确认定稿」** 按钮点亮；
   - 若出现 `WARN` 或 `FAIL`，展开 **查看检查说明**，查看具体哪一方面需要补证或修改；
5. **定稿批准**：
   - 点击 **「确认定稿」**，输入你的署名（如“作者”）与简要批准理由（如“论点充分，符合新手读者定位”）；
   - 正式版本即刻锁定，进入 `APPROVED` 状态。

---

### 场景 2：跨多篇笔记归纳与发现新选题

适合场景：积累了大量不同主题的零散笔记，不知道写什么，希望让 AI 跨资料找出有价值的碰撞角度。

1. **唤起选题工具**：
   - 按 `Ctrl+P` 输入 `从仓库发现新选题`（或点击首页候选素材组卡片上的 **深入选题** 按钮）；
2. **圈定资料范围**：
   - 勾选要参与综合的资料目录（例如勾选 `00_Inbox` 或 `读书笔记/`）；
   - 设置最大参与篇数（默认 24 篇，支持 2–60 篇）；
   - 可在“希望探索的方向”填写粗略偏好（也可留空）；
3. **核对范围与同源分组**：
   - 系统自动对正文进行去重，并将同链接、原文/转录版本的笔记归入同一个“来源组”（确保不会把同一篇文章的多个摘录当成独立证据）；
4. **启动综合**：
   - 选择本地 CLI，点击开始；
   - **阶段 1/2（分类）**：AI 归纳全部资料中的核心概念、主题与观点卡片，由程序严格提取原文片段编号；
   - **阶段 2/2（综合）**：AI 从互补、矛盾、方法迁移和共同缺口中提出 1–6 个新选题角度；
5. **采用选题**：
   - 查看生成的选题卡：展示读者收益、组合逻辑、论证计划、待补证项与最接近已有项目的差异；
   - 点击 **「采用此角度并创建项目」**，系统自动建立绑定该证据快照的项目，并直接跳转到写作台。

### 场景 3：叙事创作能力包（Narrative Pack）与多章节小说连载

适合场景：小说创作、故事讲述、三幕式大纲、长篇连载或基于真实史料的非虚构叙事。

#### 1. 选择适合的叙事 Profile
创建或配置叙事项目时，可指定 Profile：
- **`general-fiction`（通用虚构）**：注重人物内在动机、因果反转与场景冲突，避免模板化套路；
- **`serial-fiction`（连载小说）**：严格跟踪角色状态（物品/伤势/知识）、前情伏笔与章末钩子（Cliffhanger）；
- **`narrative-nonfiction`（非虚构叙事）**：坚守史实底线，事实必须严格来自引用资料，推断与事实明确区分。

#### 2. 叙事工作流执行
在写作页指令框中输入指令：
- **大纲构思（`plan`）**：
  - 指令示例：`设计前三章的冲突大纲，确立主角的核心缺陷与第一起危机。`
  - 输出：结构化大纲与初始人物/规则状态增量（State Delta）。
- **正文起草（`write`）**：
  - 指令示例：`按照大纲撰写第一章，细化飞船引擎熄火时的紧急迫降场景。`
  - 上下文装配器会自动注入 P0 核心约束与 P1 活跃角色，生成第一章 Candidate 稿件。
- **跨章连续写作（`continue`）**：
  - 指令示例：`从第一章迫降结束处继续写第二章，主角走出舱门发现异常遗迹。`
  - 系统读取上一章结尾状态，不依赖脆弱的聊天上下文记忆，确保伤口、物资与时间线无缝接续。
- **局部定向修订（`revise`）**：
  - 指令示例：`修改第三段关于老水手的对话，让他语气更加苍老警惕，不要改动前后段落。`
  - 系统执行局部最小修改，保持周围未受影响的正文完全原样。
- **独立审查（`critique`）**：
  - 启动独立审读：检查人物动机是否成立、节奏是否拖沓、是否存在吃设定或死人复活等连续性错误。

#### 3. 多章节（Multi-Artifact）独立管理
- 在同一个小说项目中，第一章、第二章、第三章作为独立的 `Artifact` 存在；
- 写作页上方下拉框可随时切换不同章节；
- **独立审查与定稿**：批准第一章不会自动让草稿状态的第二章通过审查，每个章节独立维护版本历史与审核记录。

### 四、审查、证据溯源与定稿门禁

OpenContent 的核心原则是：**AI 负责生成，Kernel 负责门禁，人类负责最终裁决**。

1. **五轴质量审查**：
   - **Evidence（证据）**：所有核心事实是否有材料支持，引文是否确为原文；
   - **Logic（逻辑）**：论证因果是否成立，反面论据是否有合理解释；
   - **Originality（独创性）**：是否存在价值增量，是否仅为原文机械拼凑；
   - **Voice（语调）**：语言是否自然，是否充斥空洞的公文腔、说教或 AI 模板味；
   - **Utility（读者价值）**：是否真正回答了读者的问题，步骤与结论是否清晰。
2. **证据链核查（Provenance）**：
   - 展开 **查看引用和原始资料**：清晰呈现 `Claim（主张）→ Evidence（引文）→ Knowledge（知识）→ Material（原始笔记）` 的完整溯源树；
   - 点击任一引用卡片，可直接高亮打开对应的底层笔记。
3. **版本保真与编辑冲突防御**：
   - 若你在 Obsidian 原生编辑器中直接修改了正文，或修改了底层关联资料，旧的批准状态会**自动失效**（变回待审查），防止出现“审查通过后被篡改却依然显示已定稿”的安全漏洞。

### 五、交付、排版与多渠道发布

文章定稿后，进入 **发布** 页面即可进行交付。

#### 1. 高颜值内联排版（三套主题）
- **优雅衬线（Serif）**：人文、思想随笔、深度长文（类似纽约客/端传媒风格）；
- **学术极简（Academic）**：严谨论文、行业报告、白皮书风格（黑白灰高对比）；
- **科技深色（Tech Dark）**：前沿极客、技术布道风格（深空灰配科技蓝霓虹）。
- 实时渲染所选主题的内联样式（所有 CSS 均转换为 HTML 行内样式，确保直接粘贴到第三方编辑器时不丢失排版）。

#### 2. 一键复制富文本
- **已批准成品**：点击 **「📋 一键复制为富文本 (已批准成品)」**：
  - 系统自动剔除正文内部的内部标记（如 `[[claim-id]]`），保留作者书写的 Markdown 链接与格式；
  - 剪贴板同时写入富文本 HTML 与干净纯文本；
  - 直接在微信公众号后台、知乎文章、飞书文档或语雀中按 `Ctrl+V` 粘贴即可。
- **未定稿草稿**：显示为 **「📋 复制草稿预览 (未定稿)」**，附带明确提示，杜绝误发布未经审核的稿件。

#### 3. 导出 Markdown 读者稿
- 点击 **「导出文章」**：在你的 Vault 中生成 `OpenContent-Exports/<artifact>-reader-v2.md`，并在 `.opencontent/handoffs/` 生成防篡改收据。

#### 4. 微信公众号草稿箱对接（可选）
- 在设置中配置你的公众号 `AppID` 与 `AppSecret`（密码通过 Windows DPAPI 硬件加密存储，绝不上云）；
- 点击 **「准备公众号草稿」**，系统将排版与封面推送到微信后台草稿箱，并回读草稿链接；
- 用户在微信后台做最终确认后点击群发。

## 六、日常维护与自检

1. **离线环境健康检查**：
   - 在 OpenContent 设置页面或命令面板点击 **「检查环境」**；
   - 10 秒内离线核验 Python、依赖版本、内核完整性与 Vault 可写状态。
2. **完全无 AI 纯手工模式**：
   - 如果未安装 Codex 或网络中断，OpenContent 完全可作为纯本地知识管理工具使用：
   - 可手动新建项目、手动从笔记捕获 Material、手动编辑 Claim 与 Evidence，并在原生编辑器中完成人工五轴评审与定稿。
3. **安全与隐私保障**：
   - 所有文章真源都是标准的 Markdown 文件，保存在你的 Vault 中；
   - 即使彻底卸载插件或删除 SQLite 缓存数据库，所有的文章、大纲、笔记和审核记录依然完整保存在你的本地硬盘中。
