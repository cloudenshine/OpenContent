# 个人未认证公众号：权限结论与 v0.4.1 修正

## 结论

用户截图显示账号为个人、暂未认证；稳定访问令牌接口显示有权限，菜单只显示部分接口类别。之前要求用户反复寻找“草稿管理、发布能力”分类，没有先核对具体 API 适用范围，这个诊断顺序有误。

应选择：**OpenContent 整理与审查 → API 新增草稿并回读 → 本人在微信后台发表 → 插件登记文章链接并复用反馈。** 不要求个人号调用自动发表接口，也不因菜单未展示就断言草稿接口被禁用。

## 官方依据及证据边界

| 问题 | 依据 | 结论 |
|---|---|---|
| 能否获取令牌 | 用户“基础接口”截图中稳定调用凭据有权限；[官方 stable_token 文档](https://developers.weixin.qq.com/doc/service/api/base/api_getstableaccesstoken.html) | 可以继续配置令牌连接，但尚未实测，且不代表有其他接口权限 |
| 新增草稿是否等同于发表 | [新增草稿 draft/add](https://developers.weixin.qq.com/doc/service/api/draftbox/draftmanage/api_draft_add.html) 适用范围列公众号/服务号 | 是草稿箱写入，应作为候选链路实测；不是把文章公开发表 |
| 个人未认证号能否通过 freepublish/submit 发表 | [发布草稿官方接口](https://developers.weixin.qq.com/doc/subscription/api/public/api_freepublish_submit.html) 的公众号适用范围为“仅认证”，定义为企业主体已认证 | 当前个人未认证账号不适用，不能通过配置 AppSecret、白名单或更换插件来补足该资质 |
| 菜单没有草稿分类是否足以判定不可调用 | 用户截图只展示当前页面分类，未提供 draft/add 的 API 结果；官方文档并未把它与 freepublish 归为同一权限 | 不能直接判定；也不能反向保证账号一定调用成功 |
| 自动发表受理是否已公开 | 官方 submit 说明成功仅表示提交受理；最终查询 0–6 分状态 | 对有资格账号仍需发表状态和正文回读；人工发表记录不能冒充 API 回执 |

上述具体适用范围来自项目当天已保存的官方页面，哈希及原始 URL 见 `market-evidence/wechat-api-sources.json`。本轮公开检索作了交叉定位，但技术结论不依赖社区文章。代理浏览器被安全策略禁止访问微信后台及开发文档；未通过其他浏览器、原始 CDP 或重取被禁止页面绕过限制。没有新取得用户账号的 API 权限结果。

## 已落实的修改

- 账号配置增加 `draft_only`（默认）和 `draft_and_publish`（明确启用）两种本地投递策略；旧配置没有此字段时默认只送草稿箱。
- 默认保留创建/核验草稿及上传封面，隐藏 API 发表操作，显示“登记后台发表结果”。
- 服务端 prepare 和 confirm 同时检查发表模式；网络预检之后、写入提交意图之前再次检查。旧预览不能绕过已收紧的模式。
- 历史发表回执仍可读取和核验，不因投递策略改变而抹去事实。
- 本地接入脚本默认创建仅送草稿箱的账号配置，不再引导个人号执行 freepublish。
- 它是本地策略，不是伪造的微信授权状态。即使选择可发表模式，微信自身仍可能返回未授权错误。

## 下一步实际接入

1. 回“基础信息”保存当前机器出口 IP 到 API IP 白名单。已在本机测得当前直连出口，私有检查记录保存在 `.validation-runtime/wechat-account-readiness.json`，不进入安装包。网络、TUN 或代理改变时应重新核对，以微信实际响应为准。
2. 由账号持有人取得 AppSecret。已保存的密钥优先使用；如果从未保存、需重置，须本人按微信验证流程处理，并确认不会影响其他使用旧密钥的应用。代理不接触后台凭据页面。
3. 双击 `Connect-WeChat.cmd`，只在本机输入 AppID/AppSecret。令牌成功后，再选真正可公开的批准稿和封面，通过明确的草稿创建与回读验证当前账号实际权限；不上传合成验收文章。
4. 如果 draft/add 明确返回未授权，则切换到已批准 Markdown 交付及微信后台人工编辑；保留真实错误码，不继续重试或以界面推断覆盖 API 事实。

无需提供更多分类截图，也无需为当前这条“草稿 → 本人发表”流程盲目购买认证、换主体或开通服务号。认证适用性与费用不在本轮建议中。
