# 同题写作比较：共用任务与限制

受众：决定是否信任生成交付物的独立创作者。

题目：为什么显示成功，不等于内容可用。

正文约500–650个中文字符，要求言之有物、自然表达、具体推理、避免空泛口号。输出所提供真实请求中 response_schema 对应的 JSON artifact。

仅可使用以下事实：
- S1：OpenContent 原 Narrative 扫榜界面未提交 raw_data；runtime 会回退到三条固定起点数据或两条固定知乎数据，并返回 SUCCEEDED。
- S2：原封面适配器写入1×1 PNG，原测试仅检查文件存在且大于50字节。
- S3：修复后的七猫真实流程在2026-10-01抓取并分析20条数据，保留URL、时间戳和哈希。
- S4：真实图片提供方执行以及Windows／Obsidian实机验收尚未完成。

解释一种实际可用的验收方法，明确它是建议而非已经普遍验证的结论。不得新增效果数字、虚构亲身经历或补造事实来源。

必须逐字保留的声明与标记：
- 文件存在，只能证明有文件，不能证明内容已经可用。[[claim-acceptance]]
- 真实封面生成与 Windows／Obsidian 实机验收尚未完成。[[claim-limits]]

方法：三个独立写作执行分别只读取旧版、1.0.0或最终1.0.1的实际提示文件，不查看其他草稿、不联网；独立评审只查看匿名样本及同一事实简报。旧版草稿被两轮重复用作参照，未重新采样。评审维度每项0–4分：事实忠实、具体推理、行动价值、自然精确表达、范围约束。

这不是本机OpenContent或Codex／Claude CLI实跑，而是隔离模型执行的单题示范。两轮评审者不同，绝对分数不可直接跨轮比较；没有多次随机重复、人类评审或统计显著性证明。字数口径（纯汉字或包含标点/英文）差异见各评审报告。
