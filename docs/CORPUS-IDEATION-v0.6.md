# v0.6 从资料组合中形成选题

## 0.6.1 真实使用故障修复

用户仓库的两次 60 份资料任务均在分类阶段失败，原因为模型返回的引文丢失 Markdown 标记、过短或串到其他来源。原先四份备忘录的模型验收不能证明该规模可用。

现将分类响应中的自由抄写引文改为来源内的 `evidence_id` 选择。程序按编号取回连续原文，保留 Markdown 和换行；不得跨取样间隙拼接，也不接受属于另一来源的编号。不降低原文完整性检查。新增 60 份资料、Markdown/CRLF、错误编号与取样间隙回归。

用户明确授权后，同一失败快照的 60 份资料已通过真实 Codex 分类与综合：60 张资料卡、11 个主题、6 条候选、0 条排除；全部原文依据精确匹配，比对范围为该快照中 1 个已有项目。脱敏收据见 [0.6.1 真实重放](ideation-recovery-v0.6.1.json)。结果基于历史快照，没有修改旧失败记录、创建项目或发表；实际 Obsidian 宿主点击路径仍未验收。6 条候选不等于 6 条已证实的原创结论，跨领域类比和可能同源的材料仍需作者复核。

“发现新选题”现在是先整理资料，再提出问题。它不再把单篇笔记的标题改成项目名称。目标已明确时的材料推荐仍保留，两者有不同用途。

## 使用路径

1. 从右侧 OpenContent 工作台打开“从仓库发现新选题”，可填写希望探索的方向。
2. 查看本轮资料数量和取样提示，选择已登录的本地 Codex / Claude。未配置时可直接在这里检测并启用，无须先建项目。
3. 点击“综合这批资料，生成选题灵感”。第一阶段归纳概念主题、关键观点和原文依据；第二阶段组合互补方法、矛盾、可迁移机制或共同缺口，并与已有项目比对。
4. 候选主要展示新问题、读者收益、组合成立的理由、论证步骤、与已有内容的差异和待补证事项。资料卡和原文引用折叠为依据，不再作为候选本身。
5. 采用某个角度后，一次创建项目并捕获相关资料。提纲、缺口、来源贡献和新颖性说明保存在项目的 editorial_brief 中，供后续创作继续使用。完整灵感报告保存在 `OpenContent-Workspace/Ideation/`。

运行可取消，关闭窗口后可从任务区重新查看。失败后刷新资料范围重试。已经采用一条选题会改变项目清单，其余旧候选需重新综合，避免沿用过期的排重结果。

## 组合与排重规则

- 每条选题至少使用两份内容不同的资料，明确每份资料承担的作用。完全相同的正文副本只算一份。
- 用过的材料可以产生新的问题。已做项目的目标、论点和稿件短摘录进入比对，不能只凭“材料已用过”排除。
- 模型标记重复的问题、与已有标题或目标精确相同的内容、照抄笔记标题及批次内精确重复会被排除，并显示原因与已有项目入口。
- 引用必须逐字来自本次摘录；未知来源、单资料候选、虚构引文和无效项目引用被拒绝。模型提出的组合是研究假设，不是已经证明的事实。
- 不强制凑数，没有成立组合时允许返回零条并说明缺少什么。语义排重与组合质量仍依赖模型判断，需要作者选择，不能保证绝对原创。

## 范围与隐私

扫描最多 3000 篇、30 MB，单篇最多 500 KB；排除隐藏目录、下划线目录、链接目录、领域数据、生成物、附件及 node_modules。正文精确去重后，按目录覆盖和方向词项相关性取样，最多选择 60 篇。长文取开头、中部和末尾共约 2400 字符，截断可能遗漏关键段落；界面明确标注未覆盖全库。方向影响排序，不是严格的目录过滤器。

已有项目最多比对 100 个，超限明确失败；每个项目的目标/论点各取前 600 字符，最多三篇稿件各取前 800 字符。该范围不能代表完整历史知识的语义索引，也没有持续增量全库聚类。

打开窗口仅准备本地范围。点击开始后摘录、分类结果和项目摘要进入所选 CLI，可能由其远端模型处理。快照、结果与诊断保存在 `.opencontent/ideation/`，本地启动 CLI 不等于离线模型。详见 [隐私说明](../PRIVACY.md)。这些内部依据不会自动追加到发表正文。

运行前、阶段返回后及采用前检查来源哈希和项目版本；发生变化时拒绝旧结果。分类和综合每阶段至少允许 300 秒，复用已有模型与推理设置。

独立 CLI 示例（插件服务运行时请使用插件入口，避免同一 Vault 两个任务所有者）：

```powershell
python -m opencontent --vault D:\YourVault discover --ideas
python -m opencontent --vault D:\YourVault ideate --direction "知识库如何支持持续写作" --provider codex
```

前一个命令只准备范围，后一个才执行模型。

## 验证证据

真实 Codex 对四篇明确编写的开发验收备忘录完成了两阶段调用，形成四个候选并排除一个重复角度。该测试没有发送用户实际 F 盘仓库内容。一个结果将“解释与检验”和“证据追溯”结合，提出“笔记何时才有资格进入草稿”的问题：理解能力与事实可靠性分开检查，再形成材料进入写作的条件。

生成结果经当前校验器复核，并实际采用为包含两份 Material 的项目；重新读取后提纲仍存在，可读报告已保存。脱敏收据见 [真实运行证据](ideation-runtime-v0.6.json)。自动检查见 [verification.json](verification.json)，包含跨资料采用、旧材料复用、假引文拒绝、重复候选拒绝、来源变化拒绝、空结果和 Windows 状态轮询竞态回归。

本轮尚未在实际 Obsidian 宿主中点击验收新选题窗口，不能把脚本与语法检查当作真实宿主 UI PASS。Claude 未执行真实模型验收。
