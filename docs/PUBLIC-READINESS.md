## 安装、恢复与 0.8 迁移

安装后的 `kernel/` 包含 opencontent 程序、CONTENT 模板和依赖清单。Python 与第三方依赖仍需本地准备；不是自带 Python 的独立应用。连接目录为空或旧目录不存在时，插件可以找到随包内核；安装器 `--configure` 明确使用随包内核并保留其他设置。

选题窗口可展开资料范围，勾选目录及篇数，查看范围和截取数量后开始。选择的是生成输入，结果仍以问题与读者价值呈现。目录选项不读取或发送模型认证文件。

0.8 任务失败时点重试可复用仍有效的分类。0.6/0.7 的选题快照缺少同源检查，更新后必须刷新范围重新综合；历史结果和失败记录仍可查看，不能直接采用旧快照绕过新检查。原始来源或项目变化需刷新范围，不能复用过时上下文。目录和数量控制目前由插件提供；独立 CLI 仍使用默认范围。

## 公开发布必须满足的验收

1. **首次安装**：在两个干净 Windows 用户环境中，按 README 安装和连接；不依赖开发者源码路径。列出 Python 未安装、依赖缺失、CLI 未登录时的真实提示和恢复步骤。完成安装、升级、回退后验证既有笔记、设置和凭据不被覆盖。
2. **完整宿主路径**：在真实 Obsidian 中完成新项目 → 限定资料 → 候选选择 → 对话改稿 → 配图方案或实际图片 → 审查 → 微信草稿回读 → 后台发表与登记 → 反馈复用。分别检查 320/440 像素侧栏、深浅主题、键盘操作和重启；模拟 DOM 和 HTTP 收据不算宿主通过。
3. **内容质量**：预先固定聚焦资料、混合资料、同源转录/摘要、证据不足四类语料，至少 12 轮。由两位独立评审按“具体读者问题、来源实际贡献、与已有稿件差异、可研究性、牵强类比/同源误用”记录原始判断。至少 80% 的有足够材料轮次产生一条双方认为值得采用的候选；不足语料应允许零条。阈值是待检验的发布要求，不是已有成绩。
4. **恢复与状态**：覆盖模型退出、超时、取消、关闭窗口、重启、断网、材料修改、检查点损坏。不得丢失用户输入、误建重复项目或自动绕过批准；用户从错误提示能找到下一步。
5. **外部试用**：至少三名没有参与实现的作者独立完成核心路径，记录所有求助和卡点，回访是否实际再次使用。未达到时继续小范围开发预览，不能上架后再让用户承担验收。

## 证据边界

自动检查以本轮 verification.json 为准。0.6.1 的真实 60 份资料收据证明当时的两阶段执行与引用完整性，不能作为 0.8 的新模型质量结论。本轮不再发送私人语料给外部模型。

本轮发现了 Windows Computer Use 原生入口，并列出了真实 Obsidian 窗口。读取窗口时应用控制授权超时，重试被自动审批拒绝；拒绝理由为超时后缺少针对该访问权限的明确授权。已请求用户明确授权，未获回应前不再访问，也不通过 CDP 或其他方式绕过。宿主验收仍未完成，不能承诺已达到公开使用高度。

同源归组限制：同源链接只支持 YAML 顶层 source/source_url/url；文件名规则采用保守长度限制，正文重合检查截取前 30000 个归一字符。跨网站转载、过短摘要或无元数据改写可能漏归组，共用通用链接或模板可能误归组。不同来源组不是独立证据的证明；仍需核对来源贡献。

0.8 安装器按版本写入 `kernel-0.8.0/`，旧内核原目录保留，避免运行服务的工作目录锁阻止更新。ZIP 手工安装仍使用 `kernel/`；插件优先选择与当前版本匹配的随包内核，外部自选源码目录保持显式选择。升级后的当前 Obsidian 进程不会热替换：下次停用再启用后才加载新版。回退先停用插件，再恢复同一备份中的界面文件和 data.json，旧版本内核目录已保留；同版重装若该版内核正占用，仍需先停用插件。
