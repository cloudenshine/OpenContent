# OpenContent 四周工作流试点

状态：方案已准备，尚未招募或获得任何实际用户数据。8–12 人和下述阈值是决策用的试点设计，不是市场统计。任何邀请、录屏或内容分享须由参与者同意；插件不上传遥测。

## 样本与基线

选择已有 Obsidian Vault、过去一个月至少写两篇教程/研究说明/通讯、愿意在未来四周完成至少两篇内容的作者。记录主要设备、现有插件和使用 Agent 经验；至少包含 3 位不熟悉 Python 的作者以暴露安装成本。当前仅已验证 Windows，其他平台单列探索，不能合并成功率。

先观察每位作者用现有方式完成一次“资料→草稿→核对→公众号草稿→发表核验→反馈复用”，记录耗时、切换工具次数、遗漏来源、返工。再用 OpenContent 完成相近任务，交替顺序以减少学习效应。题材难度与作者差异单独记录，不能当随机对照研究或统计显著效果。

## 四周任务

1. 第 1 周：不代操作安装和配置；给任务而不是按钮教程：从已有笔记捕获一段资料，确认发送范围，生成/组织第一篇稿，找到某个主张的出处。访谈只在遇到阻碍后介入并记录帮助次数。
2. 第 2 周：作者自行开始第二个真实项目；记录返回入口，是否重新捕获、审查和交付。无题材可写的人标记“不具备返回机会”，不能悄悄从总样本删除。
3. 第 3 周：在参与者愿意的测试副本里修改一个来源，观察是否理解旧批准为何失效；让作者解释如何修正。不得在其真实稿件里暗改事实。
4. 第 4 周：完成第二次可用交付；访谈哪些步骤愿意保留、替代了哪个工具、哪一步会绕开、是否愿意继续。询问支付意愿只能形成假设，不据此推算收入。

## 事件和分母

| 指标 | 定义 | 防止自欺 |
|---|---|---|
| 首次价值时间 | 从启用插件开始，到源笔记被正确捕获且用户能找回，包含安装等待 | 同时报安装时间与捕获时间，不只取最快样本 |
| 独立完成率 | 无维护者代操作完成捕获、范围确认、找到证据的人 / 所有尝试者 | 帮助、失败、放弃均记录 |
| 7 日第二项目率 | 首次捕获后 7 天内启动另一真实内容项目的人 / 已有完整 7 天观察窗的尝试者 | 不是重新打开同一个演示项目；同时给分子/分母 |
| 周有效返回 | 当周自发捕获新材料、修订、判断或交接至少一次的人 / 当周观察到的原始队列 | 打开页面、自动刷新、演示任务不算；无产出机会另列 |
| 审查误阻拦 | 作者质疑后由人工复核判定为工具错误的阻拦 / 所有被检查阻拦 | 合理的证据不足不算误报；争议列待判定 |
| 来源可核对率 | 随机抽取关键主张中，作者能回到正确原文并解释支持边界的条目 / 抽样条目 | 精确字符串存在不是语义正确 |
| 净编辑收益 | 核对和返工时间相对基线变化，同时记录新加审查负担 | 不能只报告更快生成草稿 |
| 技术可靠性 | 丢失/错误覆盖/过期批准漏拦截次数，失败恢复结果 | 任一数据损坏立即暂停扩样，先修复并复验 |

使用 [空白记录表](pilot-observations.csv)；每行一个观察事件，用自选参与者代号，不收姓名、Vault 路径或正文。用户自行决定是否分享本地记录；运行日志含正文，不默认索取。

## 建议继续/调整条件

这是一组预先写下的产品门槛，可在开始前修订，开始后保留原值与理由，避免追着结果改指标。

- 任何内容损坏、错误覆盖或过期批准被当作当前批准：停止扩样，修复后回归。
- 独立首次捕获成功率目标 ≥80%，中位总首次价值时间 ≤10 分钟；失败先修安装与入口。
- 至少半数有第二篇写作机会的参与者自发完成第二项目，且报告原始队列的对应结果。
- 对至少半数完成两篇的作者，核对来源/返工有可解释改善，且总负担没有抵消收益；同时公开负面样本。
- 若两轮迭代后仍靠催促才返回，或主要价值只有快捷捕获，重新评估目标用户和审查链重量；保留首个公众号闭环，暂缓新模型、更多发布通道与收费功能。

## 访谈提纲

请讲最近一次交稿时如何确认来源；最近一次因材料变化返工发生了什么；用现有插件最满意和最麻烦的环节是什么；刚才哪个提示看不懂；你能解释为什么这次不能批准吗；如果关闭 OpenContent，下篇文章会少什么；哪个已有工具仍不可替代；是否有明确理由下周再回来。

避免问“你喜欢这个创新系统吗”或展示架构后要求评分。先记录行为，再让参与者解释。不以维护者自评替代用户选择。

## v0.4 追加：先验证完整公众号工作

先由维护者与首位真实作者用有权限的账号完成一篇可公开文章，再扩样。以 Notebook 研究 + Obsidian 编辑 + 微信后台/现有发布工具为对照，比较总耗时、切换次数、重复录入、来源变更发现率、故障后的恢复耗时、下一篇自主复用率。记录每次确认的负担，而不是只统计拦截次数。

停止扩样条件：重复发文、错误账号投递、过期批准漏拦截、回执误报。留存假设是作者愿意回来处理资料变化、发表进度与下一篇经验；目前无真实数据证明这一假设成立。
