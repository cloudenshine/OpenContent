# 图文构建、精确改稿与小红书本地交付

本说明对应三阶段 feature checkout。沿用 MIT、Markdown/YAML 与 CONTENT.md 真源、现有 Jobs、Publication outbox 和人工批准，不改变发行版本。WeSight 的工作流是行为启发来源，本实现未引入其 AGPL 代码、模板或资源。原有写作策略的 MIT 来源说明继续见 [NOTICE.md](../NOTICE.md)。

## 作者入口

在“写作”页选择目标稿件。讨论、改稿、配图与自动 Critic 都绑定该 Artifact，多稿不能默认修改第一篇。生成结果是候选，必须点击采用；配图提示词和 `BRIEF_ONLY` 不代表已生成图片。两张同批图片可以依次点击“检查并插入到目标稿件”，自身上一次插入不会使余下候选失效，外部正文、标题、依赖或候选图片替换仍会拒绝应用。插入后回到待审查状态。

局部改稿先在原生编辑器打开所选稿件、保存并选择原文，再点击“使用编辑器当前选区改稿”。绑定标题/正文 hash、原文、范围与依赖快照，差异只应用到确切选区。frontmatter 内重复正文不参与定位，CRLF 先规范化，UTF-16 编辑器偏移转换为 Unicode 码点范围。选区或文件变化须重新捕获。

预览的三个主题、富文本复制、离线图文导出及微信公众号准备都使用 Python 权威构建。HTML 安全转义、图片完整解码、固定样式与资产 token 由同一契约生成。主题改变渲染/交付身份，不改变语义批准；新交付仍须重新确认。附件只允许 Vault 内 `Attachments`、`attachments`、`assets` 的 PNG/JPEG，不自动读取网络图片。应用策略为不超过 10 MB、2400 万像素的静态图片，不能理解为平台官方上限。

小红书入口选择当前已批准母稿并输入读者与表达意图，现有 CLI Provider 经 `xiaohongshu` Pack 生成独立文案与逐页计划。每页记录目的、来源片段、主张关联和资源。母稿变更使变体 `STALE` 并阻止旧输出；母稿批准不会批准变体。页面计划、正文及资源独立审查后，作者才能正式导出。

## 构建与门禁

正文、图注、图片字节、`pages.resources` 与母稿依赖参与审查身份。人工审查提交必须携带打开审查表时取得的 `input_snapshot`；带图片/页面/母稿依赖的旧客户端缺少快照时返回冲突。自动 Critic 从 request、Jobs 到 result 保存同一输入快照。Artifact v2 的 `claim_reviews` 逐主张保真判定由 response_schema 贯通到 Review，不仅检查五轴状态。

Kernel 的批准、advance、交付与发布门禁均校验当前依赖；纯领域函数在没有 Kernel 的文件依赖验证时拒绝外部依赖稿件。领域锁不作为外部文件不变的证明。渲染冻结图片字节，HTML、PNG、manifest 与资源复制使用相同冻结内容；完成 manifest 在 CAS 与当前批准/依赖复查通过后写入。失败目录可能保留部分文件作为负面证据，但没有新完成 manifest，也不会返回完成状态。

读者正文、文章标题、图注、微信标题/作者/摘要与页标题均禁止机器绝对路径和内部 ID。登记的正文 Claim 标记在读者输出中移除，图片 URL 中的任务 ID 通过附件边界验证，不误当可见正文。公开 HTTPS 来源可以保留；私网、回环、IPv4 映射 IPv6、缩写/八进制/十六进制 IPv4 和危险协议被拒绝。预览不发起任意 URL 请求。

ContextAssembler 将作者指令、当前稿件、设置及原始 Material 来源区分。错误对象类型、跨项目目标/来源、非法字段及模型讨论冒充证据会被拒绝；原有有测试的轻量对象输入保持兼容。必要原文不截断，超 UTF-8 字节预算明确失败，选择性状态裁剪有 omissions。

## PNG 的实际含义

PNG 是本机已安装中文字体的确定性图文排版，不是 AI 绘图。输出为真实 1080×1440 页面，并包含可编辑 copy.md、pages.md、plan.json、自包含 HTML 预览、源资源和 manifest。正文独有图片和逐页资源都复制冻结内容。字体只记录名称及 hash，不复制或分发字体文件。

`social-page.v2` 按实际字体测量行宽，禁止行首闭标点和行尾开标点，英文词在词边界换行。一个不可断开的词超过可用宽度时明确失败；不截字、不缩到难以阅读，不放宽页高溢出检查。缺字形、资源变化或超页都不返回完成包。

`LOCAL_BUNDLE_READY` 只表示正式本地交付包；不等于 `REMOTE_DRAFT`、`PUBLISHED` 或作者的内容/审美验收。渠道候选、合成独立审查与 fixture 人工批准均不等于真实作者验收。

## 兼容与恢复

保留单稿旧客户端的确定目标解析、原有纯文本 API 与原有五轴审查；多稿必须指定目标。带外部依赖的审查新增显式快照要求，客户端从 `/objects/{id}` 获取 `input_snapshot` 后随 `/reviews` 提交。纯文本无外部依赖的既有输入仍兼容。

升级前创建完整 Vault 备份，保留 Markdown outbox 和 `.opencontent/delivery-*` 恢复文件。旧 origin/main 的无 build `PREPARED`/`REMOTE_DRAFT` 记录用原始纯文本 Mistune 渲染契约验证，并核对当前批准的 context_hash、Review、Decision 与账号身份。验证通过后可以确认既有 PREPARED，或从既有 REMOTE_DRAFT 准备发表；已确认 payload 不替换为新增 h1/style 的内容。新普通构建不会走这条兼容路径。内容、审查或账号不一致时保留旧记录，先取消未投递预览或人工核对，不强行迁移载荷。

`SENDING`/`UNKNOWN`/`SUBMITTED` 只做只读回查，不重发。上传前保存上传意图，返回 URL 先落盘再核验；丢回执时找回 URL，调用图片恢复接口核验原资产，已保存 URL 不可替换。只有证明发稿写入尚未开始的 `ASSET_UPLOAD` 阶段才恢复为 PREPARED 并要求重新人工确认。读回正文要匹配 `remote_payload_hash`、上传/冻结资产身份及平台图片字节；篡改映射不能变成 REMOTE_DRAFT。

回滚保留 feature 创建的字段与交付文件，使用安装器备份恢复原插件/内核。旧内核不理解新图文 build 和 Pack，不应用其输出进行发布；恢复版本后需重新检查能力与批准。不要删除未知投递记录来解除去重门禁。

## 最终审查补充

投递确认不只比较 build_id 或可自行重算的 payload_hash，而是从当前批准 Artifact 重建完整冻结字段与 token_html，并在确认前及写入前复核。错误类型、缺失、格式错误、跨项目或递归的母稿依赖不能获得批准，也不能击穿项目面板。重复原文由准确范围和当前正文 hash 定位，不再用全篇唯一性作为额外限制。详见最终验证报告中的正常套件回归。
