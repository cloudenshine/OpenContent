# Security and compatibility checks

The desktop plugin uses an explicit Python runtime and native CLI selected by the user. It does not download, install or update itself, Python, dependencies or CLI tools. Child processes receive argument arrays with `shell: false` and hidden windows. The local HTTP server binds to `127.0.0.1`, uses a per-process bearer token, requires the correct Host and rejects browser Origins. A static runtime version check runs before startup; the live health version is also checked before reporting a successful connection.

The publication preview uses Obsidian's `sanitizeHTMLToDom`, followed by an independent allowlist that copies only text, article and table tags. Event handlers, URL attributes, user CSS, metadata, images, SVG, forms and nested browsing contexts are removed. The preview remains sandboxed with `default-src 'none'`. The article renderer escapes source text before adding fixed theme markup. Neither renderer treats model-produced HTML as trusted UI code.

Recommended lint keeps errors enabled. The exact CommonJS import allowlist covers `obsidian`, `child_process`, `path`, `fs`, `crypto` and `electron`, because this plugin entry point and its Node engines currently use CommonJS. Other imports and unsafe HTML assignments are verified with negative controls. Brand names retain their proper casing; other interface text still follows sentence case. The optional declarative-settings advisory remains enabled. The existing `display()` tab supports older Obsidian versions, as permitted by the official migration guide.

The conservative release minimum is Obsidian 1.13.7, the existing native version used for independent desktop acceptance. No application was installed or downgraded for testing. Lower native versions remain unverified and are not claimed as supported. `npm run lint:compat` uses the official type-aware `no-unsupported-api` rule and API `@since` annotations. A separate negative control deliberately checks against 1.8.0 and rejects an API introduced in 1.10.0; that historical API-contract check is not native startup evidence for 1.8.0. A user visual check remains distinct from native command, workspace-state and process evidence.

Browser preview checks use real headless Chromium and the actual production allowlist helper. A deliberately permissive sanitizer stub challenges the independent allowlist. These checks prove the component boundary under those inputs; they do not replace native Obsidian UI acceptance. Windows symbolic-link tests that require unavailable privileges remain failed or unverified. Security settings are not changed and such cases are not skipped.

Run `npm run lint`, `npm run lint:compat`, `npm run lint:controls`, `npm test`, and the Python test suite. Review the exact commit and release file hashes before publishing. Do not overwrite an existing release with different code.
