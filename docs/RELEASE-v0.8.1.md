# OpenContent 0.8.1

OpenContent 0.8.1 includes writing policy 1.0.2. This desktop release develops local notes into traceable drafts, keeps revisions as proposals until applied, and requires human approval before publication.

The conservative minimum is Obsidian 1.13.7. Independent native Windows acceptance used the installed Obsidian 1.13.7 application and a synthetic vault; lower native versions were not tested and are not claimed as supported. Python 3.12 and the pinned dependencies remain required. Community installation supplies the three UI files; configure a matching external runtime using the documented manual package. No automatic runtime installation is performed.

Changes include native npm Codex/Claude executable discovery, preserving the selected model at startup, runtime/plugin version checks before reporting a connection, custom vault configuration directories, safer publication preview HTML, preserved version history, and actionable errors. Cumulative writing, source-import and cover repairs reject unsupported or missing evidence instead of reporting sample data or placeholder images as success.

Validation: candidate Node 47/47; Python 221/224, with three Windows symbolic-link privilege cases retained as failed rather than skipped. Three new Windows regressions cover internal/external junction rejection and ordinary output paths. Fourteen independent real filesystem checks cover junction ancestors, Windows path forms, market-import hardlinks and nonregular directories. Internal workspace junctions are now rejected consistently; external junction paths were already blocked before this repair. Recommended official lint has zero errors and one optional declarative-settings warning. Positive and negative lint controls, typed API checks, version refusal, authenticated HTTP boundaries and repeated installation passed. Native UI acceptance covered home, the real synthetic draft, publication refusal for an unapproved draft, repeated panel opening and actual local-kernel disconnect/reconnect while preserving unsent text and the draft.

The actual existing CLI completed writing, targeted revision, critique and real image generation in synthetic acceptance projects. Model scores are not human quality acceptance. A minimal request with the saved MiniMax model identifier succeeded through the existing ChatGPT-authenticated CLI; its header identified the provider as OpenAI, so this does not certify a separately configured direct MiniMax endpoint or the full MiniMax workflow. Other Narrative combinations, fresh market collection and mobile/large-vault testing remain outside this validation.

Release only after reviewing the exact commit and asset SHA256 values. The new application tag must be `0.8.1`, matching the manifests, package and kernel. Do not overwrite an existing release. Author drafts, credentials, private acceptance logs and local-only integration changes are not release assets.
