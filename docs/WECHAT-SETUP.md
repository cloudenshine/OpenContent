# 微信公众号接入与验收（OpenContent 0.4.1）

首个渠道已按用户选择固定为微信公众号。当前用户是个人未认证公众号，默认采用“API 送入草稿箱 → 微信后台本人发表 → 登记链接”。只有确认具备发表权限的账号才在配置中选择“草稿及 API 发表”，使用第二次确认。没有调用群发接口。真实账号尚未配置，本仓库的软件验收回执不能当作真实微信发表凭证。

## 1. 安装与本地配置

**本工作区可直接双击 `D:\Workspaces\codex\_work\OpenContent\Connect-WeChat.cmd`。** 默认接入当前已安装的 `validation-vault`。依次输入公众号名称、AppID、AppSecret；密钥输入不显示，以 Windows DPAPI 加密保存。程序只获取访问令牌检查连接，不上传或发表文章。已有一个账号时，再次运行直接复查连接；需更新凭据时运行 `Connect-WeChat.cmd --configure`。检查结果保存到 Vault 的 `.opencontent/wechat-connection-check.json`，不含密钥或令牌。

如果账号资料还没准备好，请本人登录微信后台查找开发配置。当前代理浏览器的站点安全策略禁止访问 `mp.weixin.qq.com`，因此不能替你完成后台登录、扫码或取得密钥；这不影响本地程序调用微信官方 API 做连接验证。不要随意重置已有 AppSecret，以免影响其他已接入应用。

以下步骤用于安装到其他明确选择的 Vault；命令行接入也可以指定 `python scripts/connect_wechat.py --vault "你的 Vault 路径"`。

```powershell
cd D:\Workspaces\codex\_work\OpenContent
python -m pip install -r requirements.txt
python scripts/install_plugin.py --vault "你的 Vault 路径" --configure
```

在选定 Vault 启用插件，打开“发布与反馈 → 添加公众号”。填写账号名称、AppID、AppSecret。不要把 AppSecret 贴入聊天、Markdown 或截图。Windows 会使用当前用户 DPAPI 加密保存；也可填写环境变量名称，启动 Obsidian 前设置该变量。更新密钥使用同一账号卡片的“更新账号配置”。

微信后台必须提供相应接口权限，并配置当前机器出口 IP 白名单。点击“检查令牌连接”只核验凭据，不能证明有草稿或发表权限。官方新增草稿接口的适用范围列为公众号、服务号；官方发表接口对公众号列为“仅认证”，定义为企业主体已认证。不要把 `draft/add`（新增草稿）与 `freepublish/submit`（发布草稿）混淆。菜单分类缺失不足以直接证明草稿接口不可用；真实调用前仍不可声称已接通。[官方发表接口](https://developers.weixin.qq.com/doc/subscription/api/public/api_freepublish_submit.html)、[稳定访问令牌](https://developers.weixin.qq.com/doc/service/api/base/api_getstableaccesstoken.html)。

本次只更新了仓库和 `validation-vault` 的隔离验收安装。没有把插件装入或改写个人 Vault。

## 2. 第一篇文章

1. 捕获笔记，补充材料，明确项目目标和读者；材料库可复用已有摘录，项目页可保存计划日期。
2. 运行创作或手动维护文章。检查重要事实、证据与五轴 Review；由人批准当前版本。
3. 在稿件审查页点击“准备公众号草稿”。选择账号，核对标题，填写作者、明确摘要及封面 `thumb_media_id`。也可选 Vault 内 JPEG/PNG，点击确认上传封面；单图上限为本版保守限制 2 MB。
4. 检查预览中的账号、正文、摘要、封面素材 ID，署名并勾选后“确认送入草稿箱”。只有回读内容匹配才显示“微信草稿已核验”。素材 ID 和文字预览不能代替视觉核对封面，请在微信后台核对。
5. **个人未认证号**：在微信后台核对排版及封面并自行发表，然后从插件草稿卡片“登记后台发表结果”记录链接。无需调用 `freepublish/submit`。**具备发表接口权限的账号**：可从插件“核对草稿并准备发表”。远端草稿变化会阻止以旧批准发表。再次署名、勾选并确认后，系统调用发表接口。
6. `SUBMITTED` 代表受理，尚未发表。点击“只读查询微信回执”，直到成功或明确失败。成功需同时核对发表状态、文章 ID、微信链接和文章内容；此时才标记 API 核验发表。`published_at` 记录第一次成功核验时间，并非平台精确发表时间。
7. 录入微信后台数据、读者留言或访谈的来源与日期、观察及改进建议。人工接受经验后，可以“带入下一个项目”。经验保留出处与判断人，不自动更改全局 CONTENT.md。

微信标题限 32 字、作者 16 字、摘要 120 字；后者已按官方 2026-07-14 更新核对。[新增草稿文档](https://developers.weixin.qq.com/doc/service/api/draftbox/draftmanage/api_draft_add.html)。本版正文保守限制 20 KB，仅支持单篇图文，暂不自动上传正文图片或提供多主题排版。

## 3. 失败与恢复

| 显示 | 操作 |
|---|---|
| 待确认 | 可重新核对或取消；尚未调用内容写入接口 |
| 发送中 / 结果未知 | 不要新建同版投递。先只读查询；响应中已收到 ID 的，重启后可恢复 |
| 未收到任何 ID | 从微信后台或平台回调取得本次草稿 media_id / 发表任务 publish_id，使用“后台 ID 恢复”；内容匹配后才能绑定。拿不到 ID 时必须人工核对，无法保证自动恢复 |
| 已受理，尚未发表 | 继续只读查询；不会重新提交发表 |
| 权限或审核失败 | 按错误码修复权限、素材或内容；明确失败后才允许准备新操作 |
| 内容不一致 | 远端被修改或平台规范化超出当前比对能力。保留现场，人工核对；不会覆盖远端 |
| 已删除或封禁 | 保留历史与最新回执，转微信后台处理；不自动重发 |
| 版本过期 | 当前来源、内容或审查改变；历史回执仍保存，新投递需重新审查 |

发布查询状态按官方 0–6 分别处理。[查询发表状态](https://developers.weixin.qq.com/doc/subscription/api/public/api_freepublish_get.html)。网络超时不自动重试写入。微信没有为此流程提供可依赖的通用幂等键，不能宣称所有崩溃都可无人工介入恢复。

微信后台在最后一次读取之后仍可能被另一位编辑改动；平台缺少条件写入语义，本地比对不能消除这个极小窗口。回读不一致时必须报告冲突，不能声称批准内容一致。

## 4. 没有发表接口权限 / 需要复杂排版

可先使用有权限的草稿接口；或“交付 Markdown / Ailu”，再在微信后台排版发表。之后在稿件审查页选择“登记微信后台手动发表”，填写文章链接、时间、署名及版本核对说明。它显示为人工登记，未经 API 核验，仍可记录反馈与复用经验。如果后台正文作了实质修改，应先同步到 Artifact 并重新审查。

已发表文章的纠错、删除、替换和群发遵循微信后台能力，本版没有自动修改已发表文章的接口。来源变化会提示受影响项目及其发表记录；可人工维护原文，或修订、重审后产生新版本投递。不能把“新版本另发”宣传成“自动更新原链接”。

## 5. 首次真实验收所需

需一位账号持有人、本地配置凭据及白名单、有权限的公众号、可公开的已批准文章与合法封面。在预览中明确确认目标与正文后，才执行对应投递。保留：草稿回读、发表任务状态、文章 URL、回读比对、一次反馈与下一项目。缺任何项，报告为待验收；不要分享未经脱敏的 `.opencontent` 目录。

## 尚未取得 AppID / AppSecret

先确认是否已注册公众号。已注册者由账号持有人登录后台，按照官方 [AppID / AppSecret 获取说明](https://developers.weixin.qq.com/doc/oplatform/developers/dev/appid) 检查开发配置；此链接来自已保存的官方稳定令牌文档，其页面内容本轮未能直接访问。未注册者需本人先完成账号注册及所需认证。公众号、服务号、小程序的账号与密钥不能混用；不是安装插件后自动分配。当前具体后台菜单应以本人看到的页面为准。

没有凭据时本地工具会明确显示 NOT_CONFIGURED，不尝试猜测账号或创建测试发表。

当前用户已确认：已注册公众号，能登录后台；尚未取得 AppID/AppSecret。下一步由本人提供后台菜单截图以定位开发配置，密钥仅在本地接入工具输入。

权限分析及代码调整见 [个人账号权限结论](WECHAT-PERSONAL-ACCOUNT.md)。新增“仅送草稿箱”是本地投递策略，不代表微信已经授予草稿权限；草稿成功必须通过真实投递及回读来验证。
