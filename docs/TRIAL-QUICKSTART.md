# OpenContent 独立试用包 · 0.8 开发预览

目前没有外部试用结果。本包让以后参与的作者能自行开始，不要求分享私人笔记、密钥或真实姓名。提供给参与者之前，由维护者确认其愿意试用；本包不会发邀请或上传反馈。

## 安装

1. 解压整个包。用 Obsidian 的“打开文件夹作为仓库”选择 `SampleVault`。里面只有人工编写的测试文章，可以修改；不要把演示内容当作可靠的现实证据。
2. 启用社区插件中的 OpenContent。插件会附在右侧栏。需要 Python 3.12+；没有 Python 时，先用你信任的 Python 安装渠道安装。
3. 打开“配置连接”，Python 填实际解释器路径，项目目录留空以使用随包内核。点“检查当前填写的环境”。缺依赖时，在 `SampleVault/.obsidian/plugins/opencontent/kernel` 目录用所选 Python 执行 `-m pip install -r requirements.txt`；随后重新检查。
4. 保存并连接。首次启动会自动发现本机已安装的 Codex 或 Claude，沿用上次选择和原有模型配置；需要先在该工具自身完成登录。环境检查不会验证登录，也不会自动安装依赖。没有 AI 也能通过“更多”维护材料和稿件。

如果试用自己的仓库，先备份。在插件关闭后将 `SampleVault/.obsidian/plugins/opencontent` 的全部内容复制到你的对应目录，保留已有 `data.json`。不要只复制三份界面文件而遗漏 `kernel/`。本包未在两个全新 Windows 用户环境验证。

## 第一次任务（记录实际行为，不补写成功）

- 打开一篇笔记，在首页写一句想写什么，核对“使用当前笔记”后点“开始写作”。取消勾选则先讨论想法；不必先填写项目名称与读者。资料、稿件和讨论都在“写作”页。
- 在选题窗口只选 `Research`，查看本轮篇数和来源组，生成候选。挑一个你真的想写的问题，解释每份资料的贡献；没有值得写的题也记录。
- 给项目发讨论指令，再请求一段改稿；核对提案后应用。发送配图指令，区分“只有方案”和“有实际图片”。
- 修改一个来源，观察旧批准为什么失效。失败、取消、重启后能否找到记录并继续。不要为完成表格绕过审查。
- 交付时检查正文没有自动附加本地来源清单，但本地仍能追溯。具备公众号条件时，再按项目内预览和确认流程验证草稿回读；真实发表由账号所有者决定。未发表就标记未测试。

逐项填写 `feedback/first-use.csv`，记录求助、失败、放弃和耗时。320/440 像素侧栏、明暗主题、键盘、重启检查使用 `feedback/host-checks.csv`。这套任务不是已经取得的验收证据。

## 七天后

填写 `feedback/return-use.csv`：是否有第二篇写作机会，是否主动再次使用、完成了什么、哪里仍使用其他工具。没有机会也记录，不从分母删除。只分享你愿意提供的去身份反馈；不要默认附上运行日志、正文或设置文件。

## 退出与回退

停用插件即可停止新任务。先让正在运行的任务取消并退出，再操作文件。演示仓库可整个保留；不需要清理真实笔记。已有安装升级用源码包的安装器，可在 `.opencontent/install-backups` 找到旧版文件与设置；回退时先停用插件，备份当前插件，再恢复同一备份中的 main.js、manifest.json、styles.css、kernel 和 data.json（若存在）。不要混用不同版本文件，也不要覆盖 CONTENT.md 或 OpenContent 内的笔记。

## 质量评审

`quality/ideation-quality.json` 固定了四类、十二轮测试输入。源码包的 `scripts/evaluate_ideation.py --provider codex --output 新目录` 可用现有 CLI 重放，保留模型响应和哈希。它只检验结构与执行门禁。

两名未参与实现的评审分别填写 `feedback/editorial-review.csv`：具体读者问题、各来源实际贡献、与已有内容的差异、可研究性、是否牵强类比/同源误用、是否值得采用及理由。独立评审完成前，不把机器通过或维护者自评当作质量通过。
